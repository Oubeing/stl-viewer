# STL Viewer —— Python 实现

一个用**纯 Python** 实现的 STL / PLY 三维模型查看器。本项目重建了常见三维
查看器的核心能力：模型读写、轨道相机、**双渲染后端**（OpenGL 硬件视口 +
numpy 软件光栅化）、线框 / 实体 / 彩色 / 透明显示、光照设置、始终留在画布内的
坐标轴与贯穿画布的十字线、2D/3D 测量（长度 / 三点圆均为视图平面口径）、
X/Y/Z/视线多轴旋转、多对象场景、单位换算、多语言、旋转动画、宏录制与截图导出
（Save Picture 直接抓当前画布帧，不做重渲染）。

> 图形界面优先使用 PyQt5 自带的 `QOpenGLWidget`（VBO + GLSL，硬件深度缓冲），
> 几十万至上百万三角面也能实时旋转；没有 GL 上下文时自动回退到自研软件
> 光栅化（Z-buffer + 画家算法 + 线性增量边函数），该后端仅依赖 numpy。
> 自带 PNG 编解码器与 5×7 位图字体，**不依赖 Pillow / PyOpenGL 等额外包**；
> 命令行模式不需要 PyQt5。

## 1. 功能特性

- **模型读写**：STL（二进制 / ASCII）、PLY（含顶点色）、以及打包 / 自包含导出件中内嵌的模型。
- **双渲染后端**：OpenGL 硬件视口（`QOpenGLWidget`，VBO + GLSL，4× MSAA）为主；
  无 GL 时自动回退到 numpy 软件光栅化（Z-buffer + 画家算法）。
- **显示模式**：线框 / 实体 / 彩色（整件同色、按分量、按曲率、按法向）/ 透明。
- **光照**：预设（默认、工作室、金属、平坦…）+ 环境光 / 漫反射 / 高光调节。
- **CAD 风格相机导航**：透视 / 正交、标准视图；**光标锚点缩放**（zoom to cursor）、
  **抓取式平移**（抓住光标下的点）、**自由轨迹球旋转**（可越过极点 / 滚转）、
  中键组合键与 4 套可切换方案（经典 / CAD / CATIA / SolidWorks）、可选惯性。
- **测量工具**：点、直线（3D / 2D）、两点圆、三点圆、角度、RZ 点；长度与三点圆
  都按**视图平面**求解，圆画出来是正圆；标注叠加在画布上。
- **坐标系 / 网格 / 十字线**：坐标轴箭头与 X/Y/Z 文字在任何缩放、旋转、平移下
  都不越出画布（零点移出画面时自动切换为左下角小坐标架）；十字准线水平/垂直
  贯穿整个画布。
- **多轴旋转**：View > 旋转轴（自由 / X / Y / Z / 视线）、工具条下拉与
  `Ctrl+Shift+F/X/Y/Z/V` 快捷键；**选中的轴同时决定鼠标拖拽和「启用旋转」动画**，
  工具条按钮直接显示当前轴（如「旋转轴: X」），空格键与按钮状态始终同步。
- **多对象场景**：同时载入多个模型、分别着色与统计。
- **单位换算**：mm / inch 切换。
- **多语言**：内置 15 种界面语言。
- **旋转动画 / 宏录制**：多种轴向与速度，可录制与回放。
- **截图与导出**：PNG（含透明背景）、剪贴板，命令行批量渲染 / 转换 / 拆分。
- **MCP 服务（供 AI 调用）**：界面里可启用 / 停用的内嵌 HTTP 服务，AI 直接
  操作当前窗口的场景（15 个工具 / 4 个资源 / 2 个提示词）；含访问令牌、
  路径沙箱、工具白名单、只读 / 写权限与客户端配置一键写入；另提供无界面
  stdio 入口。见第 8 节。

## 3. 安装与运行

```bash
# 1) 安装依赖
pip install -r requirements.txt        # numpy>=1.22（必需），PyQt5>=5.15（可选）

# 2) 启动图形界面
python run_viewer.py                   # 最大化窗口启动，空场景（0 objects）
python run_viewer.py model.stl         # 启动并打开单个模型
python run_viewer.py a.stl b.stl       # 启动并同时打开多个模型

# 等价的模块方式
python -m stl_viewer model.stl

# 3) 无图形环境 / 批处理 → 命令行模式
python -m stl_viewer --cli --help

# 4) MCP 服务：日常使用直接在图形界面里配置
#    Extras → MCP Service Settings... → 启用 → 生成令牌 → 写入客户端配置（见第 8 节）
#    无界面 / 独立进程模式：
python -m stl_viewer --mcp --root .        # 零依赖 stdio 版（标准库 + numpy）
pip install "mcp>=1.2"                      # 官方 SDK 版才需要
python -m stl_viewer --mcp-sdk --root .
```

> GUI 内嵌服务随窗口启停，AI 直接操作当前场景；独立 stdio 服务由 AI 客户端
> 按配置拉起，持有自己的会话。两种模式共用同一份业务层。

> 无 PyQt5 时，直接运行会给出安装提示，命令行模式与 MCP 服务都不受影响。

> **启动状态**：窗口默认最大化，场景里没有任何 objects（不再自动生成示例
> 毛坯），Objects 面板为空；画布中央显示视图原点标记与载入提示。模型仅通过
> `File > Open`、拖放或命令行参数进入场景，载入后自动居中到画布中心。

## 4. 命令行接口（CLI）

```bash
python -m stl_viewer --cli <子命令> [参数]
```

### 4.1 `info` —— 统计模型与文件信息

```bash
python -m stl_viewer --cli info samples/drill_blank.stl
python -m stl_viewer --cli info model.stl --json   # JSON 输出
```

输出：三角形/顶点数、包围盒、表面积、体积、连通分量数、退化面数、
边界边数、非流形边数、水密性判断等。

### 4.2 `render` —— 渲染图片

```bash
# 实体 + 抗锯齿，双倍分辨率
python -m stl_viewer --cli render model.stl -o out.png --double --antialias

# 线框 + 网格 + 坐标轴，指定视角与尺寸
python -m stl_viewer --cli render model.stl -o wire.png --wire --grid --view iso

# 按连通分量着色
python -m stl_viewer --cli render model.stl -o parts.png --component-colors

# 法向彩虹图 / 平滑着色
python -m stl_viewer --cli render model.stl -o n.png --orientation
python -m stl_viewer --cli render model.stl -o s.png --smooth

# 透明背景导出
python -m stl_viewer --cli render model.stl -o out.png --transparent

# 任意朝向
python -m stl_viewer --cli render model.stl -o v.png --yaw 35 --pitch 20
```

常用参数：`-o/--output`、`--size WxH`、`--view {iso,iso_back,front,back,left,right,top,bottom}`、
`--yaw`、`--pitch`、`--ortho`、`--wire`、`--colored`（整件同色，默认）、
`--uniform`、`--component-colors`、`--curvature-colors`、`--orientation`、
`--smooth`、`--edges`、`--grid`、`--crosshair`、`--no-axis`、
`--transparent`、`--transparent-object`、`--alpha`、`--background`、`--gradient`、
`--supersample N`、`--antialias`、`--double`、`--no-weld`、`--json`。
载入时默认自动焊接重合顶点（STL 多为未焊接的三角汤），`--no-weld` 可关闭。

### 4.3 `convert` —— 转换 / 修复 STL

```bash
python -m stl_viewer --cli convert in.stl -o out.stl --ascii    # 转 ASCII
python -m stl_viewer --cli convert in.stl -o out.stl            # 转二进制（默认）
python -m stl_viewer --cli convert in.stl -o out.stl --weld --repair
python -m stl_viewer --cli convert a.stl b.stl --repair         # 批量，自动命名 *_out.stl
```

参数：`files...`（一个或多个输入）、`-o/--output`（单文件时指定输出）、
`--ascii`、`--weld`、`--repair`、`--tolerance`。输出目录不存在时会自动创建。

### 4.4 `components` —— 拆分为连通分量

```bash
python -m stl_viewer --cli components model.stl --weld \
    --out-prefix parts/part --min-triangles 1
```

参数：`file`（输入）、`--out-prefix`（输出前缀，目录自动创建）、
`--min-triangles`（小于该面数的分量跳过）、`--weld`、`--repair`。
输出命名为 `<prefix>_part01.stl`、`<prefix>_part02.stl`……

### 4.5 `measure` —— 测量计算

所有测量都以**文件为第一个参数**，用选项指定几何，点之间用 `;` 分隔：

```bash
# 两点距离
python -m stl_viewer --cli measure model.stl --line "0,0,-20;0,0,20"

# 三点定圆（圆心 / 半径 / 直径）
python -m stl_viewer --cli measure model.stl --circle "0,0,0;10,0,0;5,8,0"

# 两点定圆
python -m stl_viewer --cli measure model.stl --circle "0,0,0;10,0,0"

# 三点夹角（第一点为顶点）
python -m stl_viewer --cli measure model.stl --angle "0,0,0;1,0,0;0,1,0"

# 单点 / RZ 点（柱坐标）
python -m stl_viewer --cli measure model.stl --point "1,2,3"
python -m stl_viewer --cli measure model.stl --rz "10,0,5"

# 指定 Z 高度处的最大回转半径
python -m stl_viewer --cli measure model.stl --radius-at 5

# 英寸单位 + JSON 输出
python -m stl_viewer --cli measure model.stl --rz "10,0,5" --units inch --json
```

## 5. 图形界面

界面按常规三维查看器组织。窗口**启动即最大化且没有任何 objects**；
画布中心是默认旋转支点（可在「视图选项」改为绕按下点旋转），并有一个低调的
中心标记。鼠标导航默认采用 CAD 方案（光标锚点缩放 / 抓取平移 / 中键组合键）：

- **文件 File**：打开 / 追加 / 关闭 / 导出 STL（ASCII、二进制）/ 保存图片
  （PNG、剪贴板、透明背景版）/ 最近文件 / 退出。
- **视图 View**：标准视图（等轴、前后左右、上下）/ 透视与正交切换 /
  重置 / 适配窗口 / 视图选项（显示坐标轴、网格、十字线、边线、背景渐变，
  **导航方案 / 旋转方式 / 缩放锚点 / 旋转支点 / 惯性**、**鼠标灵敏度**
  与**拖拽画质 / 抗锯齿 / 载入时焊接顶点**等选项）。
  > **默认正交投影**：为让检测/测量严格等比例（正视圆为正圆、测量即真实尺寸），
  > 启动时即为正交；需要近大远小的立体感时用 `View > Orthogonal` 切回透视。
- **网格 Mesh**：焊接顶点 / 移除退化面 / 修复法线 / 翻转法线 /
  双面显示（Back and Front，默认关闭即剔除背面）/
  着色模式（整件同色、按分量、按曲率、按法向）/ 统计信息 / 分割连通分量 / 删除选中。
- **光照 Light**：预设（默认、工作室、金属、平坦…）、环境光/漫反射/高光调节。
- **测量 Measurement**：点、直线(3D)、直线(2D)、两点圆、三点圆、角度、RZ 点；
  标注显示在画布上；可清除。
- **附加 Extras**：旋转动画（多种轴向与速度）、宏录制/播放/存取、
  语言切换（15 种）、单位切换（mm / inch）。
- **帮助 Help**：关于对话框。

**两行工具条**（常用项不再藏在多级菜单里）：

| 行 | 内容 |
|----|------|
| 第一行「视图」 | 放大 / 缩小 / 适应窗口 / 复位中心 / 旋转角度 · **8 个标准视图按钮**（等轴测、前后左右、俯仰、后等轴测，对应快捷键 `1`~`8`）· 切换视角自动适配开关 · **旋转轴下拉（自由 / X / Y / Z / 视线）** · 正交投影 / 全屏 / 视图选项 |
| 第二行「主」 | 打开 / 保存图片 / 线框 / 实体 / 彩色 / 透明 / 棱边 / 十字线 · **着色模式下拉**、**光源预设下拉** · 5 种测量 · 旋转动画 / 统计 |

切换标准视角默认会**同时重新 Zoom Fit**，模型按新朝向铺满画布；不想自动
缩放时，取消第一行「切换视角自动适配」勾选即可。

### 着色模式

实体视图默认是**整件同色 + 光照明暗**，也就是零件本来的样子；
要"用颜色表达信息"时才切到逐面取色的模式：

| 模式 | 含义 |
|------|------|
| 整件同色（默认，`auto`） | 每个对象一种本色，明暗全部交给光照 |
| 单色平面（`uniform`） | 同上，但关闭逐顶点插值，直接看到三角面片 |
| 按分量（`component`） | 每个连通分量一种颜色，用来区分零件/毛坯 |
| 按曲率（`curvature`） | 曲率热力图，找尖边与过渡区 |
| 按法向（`orientation`） | 法向彩虹图（R/G/B = 0.5+0.5·n），看表面朝向 |

> 早期版本把默认的 `auto` 接到了法向彩虹图上，实体视图看起来像一张花花的
> 贴图 —— 这正是之前反馈的"模型显示失真"的来源，现已拆分为独立的
> `orientation` 模式。开启"载入时焊接顶点"（默认开）后，`--smooth` 或
> 设置里的"插值法向"才能让曲面呈现平滑过渡。

### 鼠标 / 键盘操作（CAD 风格导航）

交互拆成零 GUI 依赖的 `stl_viewer/navigation.py`：`resolve_action()` 负责按键映射，
`NavigationController` 管理一次拖拽会话，`camera.py` 提供低层相机运算。默认方案
`cad`，与 CATIA / SolidWorks 保持同一套操作逻辑：

* **缩放跟着光标走**（zoom to cursor）：滚轮 / 触控板缩放前后，光标下的世界点
  严格不动，透视与正交都精确。`dolly_at()` 先固定参考平面再求交，修正了旧版
  `dolly_about_center(anchor=...)` 因 `target` 被补偿、两次射线落在不同平面上的偏差。
  在「视图选项」里可切回经典的画布中心锚点。
* **平移是「抓住那个点」**：按下时记录光标下的世界点，拖动时把它贴回光标，
  透视下近处 / 远处的模型也不会漂；平移后支点仍投影在画布中心。
* **旋转可以翻过顶**：默认 `turntable`（Z 轴朝上，与原手感一致）；切到
  `arcball` 是自由轨迹球，可越过极点、可产生滚转。`set_orientation()` 把任意朝向
  反解回 yaw / pitch / roll，因此投影、拾取、fit、动画与导出代码都不需要改动。
* **旋转支点可选**：默认画布中心；切到「按下点」后点哪里就以哪里为中心旋转
  （Center on point）。
* **中键组合键**：中键+左键 / 中键+右键 = 旋转，Ctrl 或 Shift + 中键 = 缩放
  （CATIA）；`solidworks` 方案则是中键 = 旋转、Ctrl+中键 = 平移。
* **不再「发黏」**：位移严格线性、限幅放宽到 200 / 300 px（旧版 60 / 120 px 且
  对小幅位移额外乘 `0.55~1.0` 增益）；旋转量与 `rotate_speed` 严格成正比。
  拖拽中按住 **Shift** 仍是 1/4 精细模式，滚轮单档限幅 4 档防触控板跳变。
* **可选惯性**：释放后按半衰期（默认 0.12 s）衰减，与帧率无关，默认关闭。

### Zoom Fit：按当前视角精确适配

旧实现用包围盒**外接球半径** `‖hi-lo‖/2` 估算相机距离：对细长件极不准确
（`HLFΦ0.20-6.5.stl` 是 `0.2 × 0.2 × 11`，外接球半径 5.5），切到俯视只剩
十几像素，这就是「zoom fit 没匹配视图大小，显示很小」。

现在把可见对象的真实顶点（超过 20 万等间隔抽样）变换到当前相机基下，
逐点解透视投影不等式并取最大距离：

```
ndc_y = y / (tan_half · (d − z))      ⇒ d ≥ z + margin·|y| / tan_half
ndc_x = x / (aspect · tan_half · (d − z))
                                      ⇒ d ≥ z + margin·|x| / (aspect·tan_half)
```

`margin=1.10`，因此任意视角、任意画布宽高比下模型都占满约 **90%** 视口。
`fit_view()` 会先把相机视口同步为真实画布像素尺寸（窗口最大化后约
`1648×940`，而不是构造时的 `1024×768`），并在布局稳定后再适配一次。
切换标准视图默认自动重新 fit；实测该针状件等轴测占竖直 81%、前视 91%、
俯视 82%（旧版俯视只有约 2%）。

### 渲染方式：OpenGL 硬件视口为主

**为什么必须换渲染方法**：纯 numpy 软件光栅化在 84.6 万面模型上单帧要
`1.1~1.3 s`。后台异步线程只能让 UI「不阻塞」，画面仍是一秒一帧，看起来
就是「一操作就卡」；降分辨率对这种规模几乎无效，因为瓶颈在三角形数量。

现在界面优先用 `QOpenGLWidget`（PyQt5 自带，无需 PyOpenGL）：

* 顶点位置 / 法线 / 基础色交错成 VBO，**一次性上传**（该模型约 91 MB，
  首帧约 130~320 ms），之后每帧只更新 MVP / 光照 uniform；
* GLSL 里做与软件渲染器一致的双光源 Blinn-Phong 着色，硬件深度缓冲负责
  遮挡（天然没有分批排序问题），4× MSAA 抗锯齿；
* 线框 / 棱边用 `glPolygonMode(GL_LINE)` 复用同一 VBO；
* 坐标轴、网格、测量标注、中心支点标记、提示文字由透明子控件用
  `QPainter` 投影绘制（QPainter 不能直接画到 GL 的 FBO 上）。

实测（`1648×940` 画布，84.6 万面）：GL 内部约 **1 ms/帧**，事件循环连续
旋转 **≈54 fps**，鼠标事件处理 `< 1 ms`。软件渲染器继续用于**保存图片、
命令行导出**，以及没有 GL 上下文时的自动回退（`Extras/设置` 中
`UseOpenGL=False` 也可强制回退）。

### 交互流畅度：事件节流与帧调度

「任何操作都不卡」靠的是让鼠标事件循环里永远没有昂贵操作，而不是只优化单帧：

| 环节 | 处理 |
|------|------|
| 状态栏 | 拖动时不再每次格式化文本 / 发信号，合并到 70 ms 定时器刷新一次 |
| 滚轮 / 惯性 / 连续缩放 | 统一计入「导航窗口」，期间只出交互快帧；停手 160 ms 后才排一张全质量精修帧（旧版每滚一档就精修，连续滚动会逐档顿一下） |
| 交互开始 | 预测性把自适应画质上限降到 0.60，避免第一帧掉帧；停手后恢复 |
| 窗口 resize | 50 ms 防抖，拖边框不再逐像素重排渲染任务 |
| 渲染任务 | 单线程池 + 忙时只记「有待渲染」，不堆积；每帧按像素预算封顶 |
| 状态 / 拾取索引 | 预览与最终取点同用测量视图平面；投影索引**只在后台线程建**（菜单进入测量 / 视图静止 250 ms 时排队），点击绝不重建 |
| 图片导出 | **普通 Save Picture 直接抓当前画布帧**（点击返回约 3 ms），后台只剩 PNG 编码，完全不重新渲染场景；抓帧是拥有自身内存的像素副本，后台编码不会读到已释放的 QImage 缓冲。复制到剪贴板同样抓帧。透明背景 / 多分辨率这类确实需要新图的入口才后台重渲染一次，并有像素上限（12M / 16M） |
| 打开 / 导出 / 统计 | 大于 4 MB 的模型、STL 写盘、深度统计、文件大小解析都走后台任务池，菜单/快捷键立即返回 |
| 网格重活 | 复制/粘贴、修复、拆分分量、三角面相交移除在 >5 万面时进后台，小模型保持同步语义 |
| 相机运算 | 拖拽每事件只有几次 numpy 向量运算，不碰 GL、不读回像素、不重建 VBO |
| GL 视口 | VBO 一次性上传，每帧只更新 MVP / 光照 uniform；2D 叠加层独立刷新 |

交互会话状态（`_nav_active`）、惯性定时器、resize 防抖、状态栏节流都在窗口
关闭时统一停止；后台渲染线程继续沿用单任务合并策略（忙时只记「有待渲染」），
鼠标事件永远优先。

离屏合成事件实测：连续 600 次拖拽移动，事件处理 **p50 0.010 ms / p95 0.011 ms /
最大 0.06 ms**；连续 120 档滚轮共 16 ms（**每档 0.13 ms**），期间全质量精修
计时器始终关闭，停手后自适应画质从 0.60 回升到 0.85 才排精修帧。
`tests/test_navigation.py` 的 26 项纯 numpy 回归覆盖按键映射、锚点缩放、
抓取平移、轨迹球方向与惯性衰减，`tests/test_gui_smoke.py` 里另有 11 项
离屏 GUI 检查覆盖组合键、交互画质窗口与支点切换。

### 测量：在视图平面里量（长度就是屏幕投影长度）

长度测量的口径与 CATIA / SolidWorks 的「在视图里量」一致：

> **一次测量里的所有点都落在同一个视图平面上**（过第一点、垂直于开始测量时
> 的视线）。因此两点距离就是屏幕上的投影长度，**不把「往屏幕里外」的深度差
> 算进去**。TOP 视图量一条 30 mm 的台阶边，不会因为一端在凸台顶面、另一端在
> 底面而变成 30.6 mm；需要真实空间距离时，再打开
> `Measurement > True 3D Distance`（更适合在轴测视图里点真实表面点）。

实现上：

1. 打开测量工具时，把当前视图下所有可见模型的顶点投影到屏幕，按 16 像素一格
   把每个三角形的屏幕包围盒登记进二维格子索引（`stl_viewer/screenpick.py`）；
2. 点击时只查该像素所在格子里的三角形，做精确射线-三角形求交，得到**表面点**。
   表面点只用于两件事：确定第一点所在测量平面的深度，以及给出 `3D=` 读数；
   默认长度仍由视图平面点计算；
3. 索引在**后台线程**构建（`_PickBuildTask`），菜单点击 / 视图静止都不会在
   GUI 线程里跑全量投影；索引没准备好时点击直接走视图平面，投影长度照样正确，
   84.6 万面模型上点测量也不会顿一下。

为什么不用 GL 深度拾取（离屏 FBO 画两遍 + `glReadPixels`）：读回像素对驱动和
上下文状态很敏感，实际机器上一按就卡住 —— 用户报障的「第一个点就点不了」就是
它导致的。现在**整条取点路径不调用任何 GL 接口**，改成纯 numpy 计算。

| 点到什么 | 取到的点 |
|---|---|
| 模型上 | 视图平面点 + 真实表面点；默认读投影长度，`3D=` 给出真实空间距离 |
| 轮廓最外一圈像素（几何边缘差半个像素） | 吸附到最近的可见边缘，仍能拿到真实表面深度 |
| 空白处（模型外 / 背景 / 空场景） | 投影到测量视图平面（过第一点或支点），任意位置都能取点 |

配套细节：

* 状态栏标明取点来源：「取模型表面点（按视图投影读数）」/「取视图平面点（按视图投影读数）」；
* 线段结果给出 **ΔX/ΔY/ΔZ**：默认口径下是投影分量（TOP 视图量水平边时 ΔZ=0.000）；
* 两个表面点存在深度差时，结果自动附带 `3D=...`，主读数仍是投影长度；
  打开 `Measurement > True 3D Distance` 后主读数切换为三维距离；
* **三点圆是平面测量**：三个点一律取同一视图平面上的投影点，法向固定为该
  平面法向，因此画出来始终是正圆、半径就是屏幕上量到的半径。旧实现误用了
  带深度差的三个模型表面点，拟合出倾斜的空间圆，投影后变成椭圆且读数偏大；
  即便打开 `True 3D Distance`，三点圆仍保持平面口径（与 CAD 一致）；
* 预览点与最终取点共用同一个视图平面，**按下鼠标之前看到的长度就是最终结果**；
* 屏幕跨度不足 15 像素时提示「放大后再测更准」：0.2 mm 在 828 px 画布上只有
  11 px，点击精度本身就是 ±1 px；
* 测量模式下移动鼠标实时显示「橡皮筋 + 当前段长」；按 `Esc` 取消进行中的测量。

顺带修掉一个深度根因：正交视图的射线起点原先放在「过支点的平面」上，而支点
可能落在实体内部（俯视带凸台的零件时），向里发射线只能打到后半部分，顶面会被
当成底面。现在起点移到相机所在的近端平面（同一条直线，投影/缩放锚点不变），
表面深度与 `3D=` 读数才真正对应看到的那一面。

精度上限（明确写出来，避免误判成 bug）：圆柱轮廓是**相切**的，切线附近整段
圆弧被压进 1–2 个像素，点最外侧那一列像素必然落在 13° 左右的圆周上，
所以「点两条轮廓线量直径」会有约 1.5%–2.5% 的系统偏小 —— 这是光栅化极限。
量平面上的特征（台阶宽度、孔心距、端面长度）则是像素级精度。

### 两点测圆：先点圆心，圆随光标实时确定

两点测圆按标准语义实现，不是「两点当直径」：

1. **第一次点击 = 圆心**：点下立即落定圆心，并画出以该点为中心的圆；
2. 之后移动光标，**圆随光标到圆心的距离实时缩放**，同时显示虚线半径与
   `⌀直径 R半径` 读数；
3. **第二次点击 = 圆周上一点**，半径由此确定，测量入库。圆心与圆周点都在
   同一条测量视图平面内，半径就是屏幕上看到的半径，圆严格经过光标点；
   即使两点取自不同深度的表面，读数也不会被深度差放大。

配套的健壮性处理（都是「点了没反应」类问题的根因）：

* **完成一次后同工具保持激活**（连续测量），不必回菜单重新点工具；
* 两点重合 / 三点共线时**拒绝入库并保留已有点**，状态栏提示换个位置，
  不会再出现「测量凭空消失、画面什么都没有」；
* 按下鼠标后手抖移动 ≤12 px 仍算一次取点（只有明显拖动才转为旋转），
  高 DPI 屏 / 触控板下不会漏点；
* 测量中快速连点被 Qt 合成为「双击」时**不触发 zoom fit**，视角不会突然跳变。


### 交互拾取：GPU 深度拾取（选点/吸附瞬时、不卡）

选点不再依赖软件渲染器的 CPU 全量射线-三角形相交（84.6 万面单次要
`~1.1 s`，拖动选点会明显卡顿）。改为在缩小的离屏 FBO（≤1024 px）里分两遍渲染：

* 第一遍把「对象编号」写入 RGB，第二遍把「表面窗口深度」编码进 RGB（24 位精度）；
  两遍都只依赖 `GL_RGBA/GL_FLOAT` 的颜色读回，**绝不读 `GL_DEPTH_COMPONENT`**
  —— 当 FBO 深度附件是 `GL_DEPTH24_STENCIL8`（Qt 常见默认）时该组合非法、
  驱动会返回清屏值 `1.0`，导致「点在模型上却永远拾取不到」。
* 读回的 1 像素经 MVP 逆矩阵反投影回世界坐标，得到模型表面真实点；深度 24 位
  编码保证重建误差仅亚像素量级（符合 GPU 像素拾取精度）。
* 大面数模型整件同色时自动去掉逐顶点颜色、改用 uniform 上色，VBO 显存省约 1/3；
  单对象 VBO 体积 > 15 GB 时放弃上传并回退软件路径，避免 OOM。
* 实测 84.6 万面模型：拾取一次 < 10 ms（含两遍渲染 + 读回 + 反投影）。

> 注：PyQt5 的 `QOpenGLFunctions.glReadPixels` 在本机只接受 `GL_RGBA/GL_FLOAT`
> 并返回浮点元组，旧式指针形式会抛 `TypeError`、`UNSIGNED_BYTE` 会抛
> `ValueError`；此处已统一用浮点元组读回再把 8-bit 值还原为整数。

### 高分屏 / Windows 缩放适配

`QOpenGLWidget` 的内部帧缓冲尺寸是「逻辑尺寸 × 设备像素比（DPR）」。若
`glViewport` 仍用逻辑尺寸，模型会被画到帧缓冲左下角（典型表现：高分屏 /
缩放屏下模型只占画布一角、各种变换越不出该区域）。现在 `resizeGL` 与
`paintGL` 都通过 `_fb_size()` 乘上 `devicePixelRatioF()`，缩放屏下模型也能
遍及整个画布、变换不再受限。

### 软件回退路径的画质与调度

**后台异步渲染**：软件光栅化放进单线程工作池，GUI 线程只合成已完成的
位图；任务携带状态快照，忙时只记「有待渲染」不堆积，提交一帧约 `0 ms`。

**渐进式渲染 + 像素预算**：视图变化先出快帧，空闲 `90 ms` 后精修；
交互帧按窗口面积封顶 80 万像素、精修帧按 `w·h·ss²` 封顶 220 万像素。
静止帧始终 1:1 全分辨率、不做平滑放大；降分辨率位图由高度反推宽度
（`w = round(W·h/H)`），宽高比严格一致，不会拉扁/拉长。

**自适应分辨率**：拖拽 / 动画期间上限默认 85%，按实测帧耗时往 30fps
收敛（下限 35%，带 1.5×/0.5× 迟滞，避免忽清忽糊）。

**打开大模型不做深度统计**：`Mesh.statistics(deep=True)` 在 84 万面模型上
要十几秒（连通分量 / 边使用计数）。打开文件时只用面数显示提示；
`Statistics` 对话框对 > 20 万面的模型自动跳过深度统计，避免点一下就冻住。

**鼠标灵敏度可调**：`View > 视图选项` 三个滑条，旋转 / 平移 / 缩放默认
`0.12 °/px` / `1.0` / `0.07`。

### 显示失真的四处根因修复

1. **反向绕序三角形深度取反**：边函数已乘绕向符号，重心坐标的分母却仍用
   带符号 `area`，约一半三角形（背面）的 NDC 深度变成相反数，远面因此
   通过深度测试盖住近面 —— 实体看起来半透明、内部螺旋槽透出来。分母改为
   `1/|area|`，`samples/preview_solid.png` 可直接看到修复后的实心表面。
2. **同批内遮挡顺序**：不透明路径按 bbox 尺寸分桶后批内不再按深度排序，
   而 numpy 对重复像素下标只保留最后一次写入，全局 Z 缓冲管不了同一批的
   覆盖。现在每个分桶内部统一按「远 → 近」排列。
3. **投影口径不一致**：透视投影矩阵没纳入 `zoom`（`visible_height` /
   `world_per_pixel` 却除了），`Camera.up()` 也未与视线正交，导致缩放无效、
   平移不跟手、拾取偏移。现在投影 / 屏幕射线 / 平移共用同一口径：
   `project → ray_to_plane` 往返误差 `< 1e-14`，平移 45 px 恰好位移 45 px。
4. **背面 Z-fighting**：默认不剔除背面时，封闭实体的背面三角形会在共享
   深度处与正面抢像素，放大看是一条条细缝与斑点。现在默认剔除背面，
   表面更干净、实测还快约 35%；需要观察开放曲面背面时用
   `Mesh > Back and Front` 打开。

## 6. 关键实现说明

- **软件光栅化**：三角形填充使用规范化重心坐标，`edge` 与深度均以
  `c + d·j` **线性增量**方式计算，深度只在真正命中的像素上求值
  （不再构造整幅 `(B,mh,mw)` 中间数组）。
- **按尺寸分桶分批**：一批三角形共用一块 `(B, mh, mw)` 矩形。若直接取批内
  `max(bw)/max(bh)`，一个 31×170 的三角形会把同批全部撑成 31×170，
  实测空洞率达 **8.0×**；改为按 bbox 边长的 2 次幂分桶后降到 **2.0×**，
  光栅化耗时随之下降一半以上。不透明路径遮挡由 Z 缓冲保证，分桶不影响正确性；
  透明混合路径仍保持全局"远 → 近"分批。
- **命中像素解算**：用 `flatnonzero` + `divmod` 由线性下标反解 `(批, 行, 列)`，
  再用 `row_base[tri] + ry*W + rx` 求像素下标 —— 只在 B 个元素里随机取值，
  比按 `(B*mh)` 规模去 `ys.ravel()` 里取快约 3 倍。
- **缓冲复用**：`color/depth/alpha` 三块全尺寸数组按渲染尺寸缓存复用，
  超采样时不再每帧 malloc/free 数十 MB；降采样直接对 uint8 视图分两步求和，
  省掉一份全尺寸 float32 副本。
- **坐标约定**：`Z` 为旋转 / 回转轴（朝上）。
- **载入自动焊接**：STL 常把同一个几何点按三角形重复存储（三角汤），
  不焊接时每个三角形都是独立连通分量 —— 体积算不出、边界边满天飞
  （示例件 4212 顶点 / 4212 条边界边 → 焊接后 1027 顶点 / 640 条）。
  容差取包围盒对角线的 `1e-6`，可用 `--no-weld` 或视图选项关闭。
- **PNG**：`png.py` 自行实现 zlib + 逐行滤波，支持 8 位非隔行、全部滤波器，
  读写均不依赖第三方库。
- **字体**：`font5x7.py` 内置 5×7 位图字形，用于画布上的标注与 HUD 文字。
- **测量**：支持 `point3d`、`line3d`、`line2d`、`circle2p`、`circle3p`、
  `angle2d`、`rzpoint` 七种类型；`rzpoint` 输出柱坐标 (R, Z, θ)。
- **内嵌模型提取**：`stl_io.extract_embedded_mesh` 可从 `.exe` / `.stpack`
  中扫描并解出内嵌的 STL / zlib 流，以兼容"自包含导出件"。

### 实测性能（Windows / CPython 3.13 / Qt 5.15 / OpenGL 4.6）

| 场景 | 模型 | 帧耗时 | 交互表现 |
|------|------|--------|----------|
| GL 视口，1648×940 | `HLFΦ0.20-6.5.stl`，845,976 面 | GL 内部 ≈1 ms | 事件循环连续旋转 **≈54 fps** |
| GL 视口，1648×940 | 同上，首次上传 VBO | 130~320 ms（一次性） | 之后每帧只更新矩阵 |
| GL 视口，1648×940 | 示例件 1,404 面 | ≈1.6 ms | 硬件 MSAA，静止/拖拽同样清晰 |
| 软件回退，1170×824 | 845,976 面 | ≈1.1~1.3 s | UI 不阻塞，但画面更新慢 → 应优先用 GL |

> 硬件视口的原因。没有 GL 上下文时程序仍可用，只是这类模型交互会明显变慢。

## 8. MCP 服务（界面配置，供 AI 调用）

STL Viewer 内置一个 **MCP（Model Context Protocol）服务**。启用后，AI 客户端
可以直接操作**当前窗口里的场景**：找模型、载入模型、统计、切视角、测量、
渲染图片并直接看到结果，界面同步刷新。服务的启用、端口、令牌、权限和客户端
注册全部在图形界面的设置页完成，不需要改配置文件，也不需要命令行。

### 8.1 运行形态

| | GUI 内嵌服务（默认交付形态） | 独立 stdio 服务 |
|---|---|---|
| 入口 | `Extras → MCP Service Settings` | `python -m stl_viewer --mcp --root .` |
| 传输 | Streamable HTTP `http://127.0.0.1:8765/mcp` | stdin/stdout JSON-RPC 2.0 |
| 会话 | **共享当前窗口的场景 / 相机 / 测量** | 独立进程、独立场景 |
| 配置 | 设置页（持久化到 INI） | 命令行 `--root` |
| 适用 | 人正在用界面，同时让 AI 协助检查模型 | 无界面 / 无人值守 / 脚本批处理 |

服务默认**关闭**，首次使用需要显式启用。工具条按钮与状态栏会显示
`○ MCP 未启用 / ● MCP 已启用`，点击即可打开设置页；`Extras → Enable / disable
MCP service` 可一键启停。启用并勾选「随程序启动」后，每次打开窗口自动拉起。

### 8.2 启用流程

1. `Extras → MCP Service Settings...` 打开设置页（四个分类页：服务 / 安全 /
   工作区与默认值 / AI 客户端）。
2. 在「服务」页勾选**启用 MCP 服务**，确认端口与工作区根目录，点「启动」；
   状态变为「运行中」后可用「测试连接」验证。
3. 在「安全」页点「生成新令牌」（也可在令牌框上右键生成 / 复制）；令牌只存在
   本机设置里。
4. 在「AI 客户端」页确认 `mcp.json` 路径，点「写入客户端配置」。写入前会生成
   `.bak` 备份，只更新 `stl-viewer` 这一条，不破坏已有服务。
5. 在 AI 客户端的连接器管理页**信任 / 重载**该自定义连接器，即可开始对话。

之后可以让 AI 执行：「列出工作区里的 STL，载入 drill_blank，统计面数和体积，
再渲染一张 TOP 视图」—— 它会依次调用 `list_models` → `load_model` →
`inspect_model` → `set_view` → `render_picture`，窗口里的模型、视角和图片同步
变化。设置页的「请求日志」实时显示每一次调用。

> 修改端口、令牌、工作区或权限会重启服务，已连接的 AI 客户端会短暂断开，
> 重新写入客户端配置后即可恢复。

### 8.3 参数一览

| 分类 | 参数 | 默认值 | 作用 |
|---|---|---|---|
| 服务 | 启用 MCP 服务 | 关 | 服务总开关，菜单 / 工具条 / 设置页三处同步 |
| 服务 | 随程序启动 | 开 | 打开窗口时自动启动服务 |
| 服务 | 监听地址 | `127.0.0.1` | 固定回环地址，不对外暴露 |
| 服务 | 端口 | `8765` | 服务地址 `http://127.0.0.1:<port>/mcp` |
| 安全 | 要求访问令牌 | 开 | `Authorization: Bearer <token>` 或 `X-API-Key` |
| 安全 | 访问令牌 | 首次生成 | 设置页可生成 / 显示 / 复制；右键菜单同款 |
| 安全 | 允许改动当前场景 | 开 | 关闭后 `load_model` / `set_view` / `measure` 等被拒绝（只读） |
| 安全 | 允许写入文件 | 关 | 控制 `export_stl` / `split_components` / 带 `path` 的 `render_picture` |
| 安全 | 启用的工具 | 全部 15 项 | 白名单；`tools/list` 只返回允许的工具 |
| 工作区 | 工作区根目录 | 当前目录 | 所有读写路径的沙箱，`realpath + commonpath` 校验 |
| 工作区 | 图片像素上限 | 2,000,000 | 防止 base64 图片撑爆 AI 上下文 |
| 工作区 | 默认单位 / 测量口径 | `mm` / 投影长度 | 与界面 CAD 口径一致；可改为 inch / 3D 距离 |
| 工作区 | 默认图片尺寸 | 640 × 480 | `render_picture` 未指定宽高时使用 |
| 工作区 | 记录请求日志 | 开 | 设置页显示最近 300 条请求 |
| 客户端 | 配置文件路径 | `~/.workbuddy/mcp.json` | 一键写入 / 复制 / 移除 / 打开 |

全部参数写入应用 INI 的 `[MCP]` 段（`AppSettings.mcp`），与视图选项、单位、
相机一起保存；「恢复默认」不会清空已有令牌。

### 8.4 安全边界

- 只绑定 `127.0.0.1`，校验 `Host` / `Origin`，防止 DNS rebinding 与网页跨站调用；
- 默认要求 Bearer 令牌，令牌用 `secrets.token_urlsafe(32)` 生成；
- 路径沙箱：AI 给出的所有读写路径必须落在工作区内，`realpath` +
  `commonpath` 双重判定，跨盘符与 `..` 一律拒绝；
- 权限分级：工具白名单、只读模式、写文件开关三道，可按需收紧；
- 请求体上限 8 MB、图片像素上限可配、业务错误以 `isError: true` 返回，
  AI 能读到原因并自行修正参数；
- HTTP 日志只写到设置页与内存，不写 stdout，不污染协议流。

### 8.5 AI 客户端配置

设置页「AI 客户端」页会生成并写入如下条目（与 WorkBuddy / Claude Desktop
的 HTTP MCP 配置格式一致）：

```json
{
  "mcpServers": {
    "stl-viewer": {
      "type": "http",
      "url": "http://127.0.0.1:8765/mcp",
      "headers": { "Authorization": "Bearer <访问令牌>" }
    }
  }
}
```

- **WorkBuddy**：路径是 `~/.workbuddy/mcp.json`（注意不是 `.mcp.json`）；
  写入后在连接器管理页的自定义连接器上点「信任」并重新加载客户端。
- **其它支持 MCP 的客户端**：把预览内容合并进它的 `mcpServers`，重启客户端。
- 端口或令牌变更后必须重新写入配置；停用服务后 AI 无法连接，`/health`
  仍可用于检查本机服务是否在线。

### 8.6 独立进程模式（无 GUI）

不需要界面、或希望 AI 客户端自行拉起进程时，用 stdio 入口。这两种模式使用
**同一份业务层**，只是传输不同，且默认开放全部工具（参数由命令行控制）：

```bash
python -m stl_viewer --mcp --root .        # 零依赖（标准库 + numpy）
pip install "mcp>=1.2"                      # 官方 SDK 版才需要
python -m stl_viewer --mcp-sdk --root .
```

客户端注册示例（把路径换成实际项目根目录）：

```json
{
  "mcpServers": {
    "stl-viewer": {
      "command": "python",
      "args": ["-m", "stl_viewer.mcp_stdio", "--root", "E:/zone6/stl-viewer-py-main"],
      "env": {"PYTHONIOENCODING": "utf-8",
              "PYTHONPATH": "E:/zone6/stl-viewer-py-main"}
    }
  }
}
```

stdio 模式下 stdout 只输出协议消息，日志写 stderr；Windows 上已把
stdin/stdout 重配置为 UTF-8。AI 客户端重启会重新拉起进程，场景随之清空，
这是符合预期的。

### 8.7 实现结构

```
AI 客户端 ──HTTP(Streamable HTTP + Bearer)──> mcp_http.py
                                               │ 鉴权 / 会话 / SSE / 日志
                                               ▼
                                         mcp_runtime.py ──Qt 跨线程桥──> 当前 GUI 场景
                                               │                       （scene/camera/measures）
                                               ▼
                                         mcp_service.py ──> mesh / stl_io / camera /
                                               ▲             measure / renderer / png
                                               │
AI 客户端 ──stdio(JSON-RPC 2.0)──> mcp_stdio.py 或 mcp_fastmcp.py
                    ▲
            mcp_config.py（设置与客户端注册）  mcp_dialog.py（设置界面）
```

| 文件 | 职责 |
|---|---|
| `mcp_config.py` | MCPSettings、令牌生成、端口探测、客户端 `mcp.json` 合并写入（含备份与原子替换） |
| `mcp_http.py` | 内嵌 Streamable HTTP 服务：POST /mcp、GET SSE 长连接、DELETE 会话、/health、鉴权 |
| `mcp_runtime.py` | Qt 控制器：启停 / 重启、跨线程调用桥、场景快照、状态与日志信号 |
| `mcp_dialog.py` | 四个分类页的设置界面：启停、令牌、权限、工具白名单、客户端配置 |
| `mcp_service.py` | 传输无关的业务层：15 个工具 / 4 个资源 / 2 个提示词 + 策略执行 |
| `mcp_stdio.py` | 零依赖 stdio JSON-RPC 服务器（握手、通知、错误码） |
| `mcp_fastmcp.py` | 官方 MCP SDK 适配（兼容 1.x `FastMCP` / 2.x `MCPServer`） |

HTTP 服务在后台线程，场景对象属于 GUI 线程：会读写场景的工具调用都通过 Qt
信号排队到 GUI 线程执行；`inspect_model` / `render_picture` / `export_stl` 等
耗时工具先在 GUI 线程做一份只读场景快照，再回后台线程计算，因此 AI 出图时
窗口仍可拖动、切视角、点菜单。

工具：`server_info`、`list_models`、`load_model`、`list_objects`、
`inspect_model`、`remove_object`、`clear_scene`、`set_view`、`measure`、
`list_measurements`、`clear_measurements`、`render_picture`、`section_radius`、
`export_stl`、`split_components`；资源：`stl://scene/objects`、
`stl://scene/measurements`、`stl://guide/measurement`、`stl://guide/tools`；
提示词：`inspect_model`、`measure_plan`。

### 8.8 故障排查

| 现象 | 处理 |
|---|---|
| AI 客户端报连接失败 | 确认设置页状态是「运行中」；点「测试连接」；检查端口是否被占用 |
| 返回 401 | 令牌不一致：重新生成令牌后必须重新写入客户端配置并重载客户端 |
| 客户端一直等待 / 协议错乱 | 端口上跑的不是本服务，或代理把请求转发到了别处；换端口重试 |
| AI 说工具不存在 | 该工具未在「启用的工具」白名单里，或使用了旧版本客户端缓存，重载客户端 |
| AI 写文件被拒绝 | 「允许写入文件」默认关闭，在设置页开启后重新调用 |
| 路径越界 | 把文件放进「工作区根目录」，或把根目录改成模型所在目录 |
| 换 SDK 版本后导入失败 | 1.x / 2.x 类名不同；`mcp_fastmcp.py` 已做双重兼容，手写 stdio 版不受影响 |

## 9. 版本记录

### v1.0.0（本版本 —— 初始发布）

初始发布版本，围绕「检测/测量工具好用、显示正确、不卡」做了系统性
打磨，关键特性如下：

1. **默认投影改为正交（Orthographic）—— 修复「圆不圆 / 缩放非等比例」**。
   透视投影的近大远小与离轴椭圆，正是检测/测量工具下「模型缩放不是等比例、
   圆缩放不圆」的根因。正交投影严格等比例：正视的圆保持正圆、缩放保持等比例，
   且测量读数直接等于真实尺寸。仍可用 `View > Orthogonal` 切回透视（需要
   近大远小的立体感时）。
2. **测量取点重构为纯 CPU 屏幕投影索引**（`stl_viewer/screenpick.py`：
   16 px 格子 + Möller–Trumbore 精确求交 + 边缘吸附）。整条取点路径不调用任何
   GL 接口，点击必定命中真实表面点 —— 修复此前「第一个点就点不了」（GPU 深度
   拾取在本机读回像素时卡死所致）。画布任意位置都能拾取（空白处退回视图平面），
   手抖 ≤12 px 仍算一次取点，高 DPI / 触控板下不漏点。
3. **两点测圆按标准语义实现**：先点圆心、圆随光标实时确定；圆心与圆周点落在
   同一条测量视图平面内，半径就是屏幕半径，两点深度不同也不会被放大。
4. **测量交互健壮性**：测量中按 `Esc` 取消；完成一次后同工具保持激活（连续测量）；
   两点重合 / 三点共线时拒绝入库并提示；测量态下双击/拖动不误触 zoom fit 或取点。
5. **Zoom Fit 按当前视角精确适配**：把可见顶点变换到相机基下、逐点解投影不等式
   （`margin=1.10`），任意视角、任意宽高比下模型都占满约 90% 视口，细长针状件
   不再缩成几像素。
6. **HiDPI / Windows 缩放适配**：`glViewport` 乘 `devicePixelRatioF()`，修复高分屏
   / 缩放屏下模型被挤到画布左下角、变换越不出该区域。
7. **84.6 万面大模型**：界面优先 `QOpenGLWidget`（VBO + GLSL，≈1 ms/帧、连续旋转
   ≈54 fps），软件光栅化仅用于保存图片、命令行导出及无 GL 时的自动回退。
8. **显示失真四处根因修复**：反向绕序三角形深度取反、同批内遮挡排序、投影口径
   统一（`project → ray_to_plane` 往返误差 `< 1e-14`）、默认剔除背面（表面更干净、
   快约 35%）。
9. **操作体验**：启动即最大化、默认以画布中心为旋转支点（不再绕世界原点转）、
   拖拽中降分辨率不卡、`shutdown()` 的 GIL 死锁修复、两行工具条（8 个标准视图
   按钮 + 自动适配开关 + 5 种测量）。
10. **CAD 风格导航 + 全流程流畅度**：新增零 GUI 依赖的 `navigation.py`，提供
    classic / cad / catia / solidworks 四套按键映射（含中键组合键）、
    **光标锚点缩放**、**抓取式平移**、**可越过极点的自由轨迹球旋转**、绕按下点
    旋转与可选惯性；位移改为严格线性并放宽限幅。事件侧把状态栏、resize、
    精修帧、惯性统一交给定时器合并，滚轮 / 连续缩放纳入交互画质窗口，
    停手后才出一张全质量帧。详见第 5 节。
11. **测量长度口径与 CAD 对齐（修复「长度差得太多」）**：同一测量内所有点都
    落在过第一点、垂直视线的**测量视图平面**上，主读数就是屏幕投影长度；
    表面点另存，深度差不可忽略时以 `3D=` 附带显示，`Measurement > True 3D
    Distance` 可把主读数切到真实三维距离。顺带修正正交射线起点落在支点平面
    导致「顶面被当成底面」的深度错误 —— 这也是圆准、长度不准的另一半原因。
12. **全流程后台化（修复「点 Save Picture 反应慢」）**：截图先弹文件框，渲染与
    PNG 编码进后台（点击返回 **0.4 ms**，实测）；复制到剪贴板、STL 导出、
    大于 4 MB 的模型载入、深度统计、文件大小解析、大网格复制/修复/拆分都走
    统一后台任务池；测量拾取索引也改后台构建（14 万面同步建需 102 ms，
    菜单入口返回 **0.64 ms**）。单张 / 多分辨率导出分别限制在 12M / 16M 像素。
13. **测试套件梳理**：改用 pytest 跑 `test_core.py` 与 `test_navigation.py`、
    其余回归脚本各自携带 `check()` 框架直接运行（详见第 7 节）。
14. **坐标系不越界 + 三点圆回归平面口径**：坐标轴箭头按方向裁进安全矩形，
    X/Y/Z 文字坐标一并夹进画布；工件零点被平移出画面时自动改画左下角小坐标架
    （软件渲染与 GL 叠加层共用同一份几何）。三点圆不再用带深度差的三个表面点
